DAY 13

端侧 LLM 推理框架

比较 Runtime、Backend 与编译型框架

学习目标

建立 GGUF/计算图/runtime/backend/kernel 的分层模型，知道如何选择 llama.cpp、MLC、ONNX Runtime GenAI 或 ExecuTorch。

核心概念

  • CPU/GPU/NPU backend
  • layer offload 与子图切分
  • 预编译与运行时编译
  • CLI、HTTP server、benchmark
  • fallback 与可观测性

嵌入式类比

框架像 RTOS + 驱动抽象：上层调度统一，下层按目标芯片替换 backend；不支持的指令需要明确回退。

本章讲解

Runtime、backend、kernel 是三层

Runtime 管图与请求，backend 把可支持子图交给 CPU/GPU/NPU，kernel 执行具体算子。ONNX Runtime 的 EP 按能力分区；ExecuTorch delegate 也经过 AOT 预处理和 runtime 初始化/执行。

先测 CPU，再测卸载

官方 ONNX Runtime 移动端指南建议量化模型先从 CPU EP 开始；若不满足目标，再尝试 NNAPI/CoreML 等。模型分区过碎时 copy 可能让“用了 NPU”反而变慢。

动手实验

对同一模型分别跑 CPU、GPU offload 或 NPU delegate，整理“可用内存—吞吐—功耗”三列结果。

工程陷阱

避免误判：只记录“已启用 GPU/NPU”而不检查执行 provider、子图分区与 fallback，会把 CPU 运行误判成硬件加速成功。
