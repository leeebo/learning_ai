DAY 10

KV Cache

用内存换取 Decode 阶段的重复计算

学习目标

理解 Prefill/Decode、K/V 张量布局、cache 量级与长上下文代价。

核心概念

  • Attention 的 Q/K/V
  • Prefill 与 autoregressive Decode
  • cache shape 与 layer/head
  • paged KV、滑窗与量化

嵌入式类比

像网络协议缓存已确认的 header：新 token 只带来新的 Q/K/V 增量，不必重新解析整段历史 payload。

本章讲解

KV cache 把时间换成空间

自回归生成中，历史 token 的 K/V 不必每轮重算；Prefill 建立 prompt 的 cache，Decode 每步读取历史并追加一个 token。它像缓存已经解析的协议头，新包只处理增量。

用公式先做容量预算

近似字节数为 layers × 2(K+V) × tokens × kv_heads × head_dim × bytes_per_value，再乘 batch/并发等因素。GQA 通过减少 kv_heads 降低容量和读带宽，但这是模型架构选择，不是 runtime 随手能开启的开关。

流程图

Prompt tokens ──Prefill──► K,V cache
New token ──Q + cached K,V──► attention ─► next token ─► append cache

代码或命令示例

kv_bytes ≈ layers * 2 * tokens * kv_heads * head_dim * bytes_per_value
# 2 = K + V; batch、dtype、GQA 会改变实际值

动手实验

做一个 KV cache 计算器：改变 context、层数、KV heads、head_dim、dtype，观察 PSRAM/显存占用。

工程陷阱

避免误判：只按权重文件估 RAM 而忽略长 prompt 的 KV cache，会导致模型“加载成功、请求一长就 OOM”。
