DAY 07

内存、带宽、MCU/NPU

从“能跑”进化到“跑得稳”

学习目标

用峰值 RAM、持续带宽和算力预算解释端侧性能，而不是只看参数量。

核心概念

  • Flash/RAM/PSRAM/Cache
  • 峰值活跃内存
  • 算力 roofline 直觉
  • DMA、对齐与零拷贝
  • NPU delegate 与 fallback

嵌入式类比

Flash 像仓库，RAM 像工作台，cache 像手边料盒，带宽是搬运工速度；模型小不代表工作台峰值小。

本章讲解

RAM 是工作台，不是仓库

Flash 中的权重、RAM 中的激活、workspace、I/O buffer 和任务栈共同形成峰值。模型文件能放入 Flash 并不表示推理瞬间有足够可用 SRAM。

DMA、PSRAM 与 cache 有不同契约

ESP-IDF 指出 DMA buffer 通常需位于可 DMA 的 DRAM 且对齐；PSRAM 通过 cache 访问，大块访问会受带宽和 cache 驱逐影响。涉及 DMA 的系统还需按芯片和 API 处理 cache 同步。

流程图

Flash weights ─mmap/copy─► RAM/PSRAM ─► cache ─► MAC unit
                              ▲ DMA / zero-copy

代码或命令示例

peak = weights + activations + workspace + io_buffers
if peak > available_ram:
    reduce_resolution_or_batch()
    enable_streaming_or_tiling()

动手实验

给定模型层表，估算每层 activation 与 workspace 峰值；用不同输入分辨率画 RAM/latency 曲线。

工程陷阱

避免误判：把“PSRAM 容量大”当作“可替代内部 SRAM”会导致 DMA 不可用、带宽下降或 cache 一致性问题，尤其在相机和显示流同时运行时。

核心测试

完成 3 道单选题后提交；提交前不会显示答案。

1. 端侧推理峰值 RAM 预算应至少包含？
2. ESP-IDF 的 MALLOC_CAP_DMA 对经典 ESP32 的含义更接近？
3. 为什么带宽受限模型增加 MAC 单元未必变快？
