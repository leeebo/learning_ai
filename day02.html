DAY 02

训练与推理

理解离线训练与设备端执行的边界

学习目标

区分训练图、推理图和部署图，知道哪些状态必须保留、哪些可以折叠。

核心概念

  • epoch、batch、学习率与优化器
  • 训练态与推理态
  • BatchNorm folding、常量折叠
  • 端侧只执行 forward 的原因

嵌入式类比

训练像在实验室调试协议栈，推理像把确定好的状态机烧进设备；设备不应携带训练时的梯度、优化器和临时统计。

本章讲解

训练固件与推理固件不是同一个产物

训练需要样本、梯度、优化器状态和随机扰动；推理只需要确定的计算图、权重和必要的运行时 buffer。把它类比为实验室里可改寄存器的调试环境，和烧录到量产板上的确定状态机。

导出前先固定推理语义

PyTorch 的 model.eval() 会让 Dropout 和 BatchNorm 使用推理行为。导出用的 example input 不是装饰：它帮助捕获图、shape 和算子路径；随后要用相同输入比较源框架与 runtime 输出。

流程图

数据集 → 训练循环 → checkpoint → 导出/优化 → runtime → 输入 → 输出

代码或命令示例

model.eval()
with no_grad():
    output = model(input)
export(model, example_input, format="onnx")

动手实验

对比训练态/推理态的 BatchNorm 输出；导出前后固定随机种子，验证误差与算子列表。

工程陷阱

避免误判：只在 PC 上比较模型文件而没有比较设备端前处理，会把颜色空间、量化和 resize 的错误误判为“模型精度下降”。

核心测试

完成 3 道单选题后提交；提交前不会显示答案。

1. 为什么推理前要调用 model.eval()？
2. 哪项通常不应随 MCU 推理产物部署？
3. 导出模型的 example input 最主要的作用是什么？
